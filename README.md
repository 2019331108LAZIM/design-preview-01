# Cosmos Foundation — frontend

Static HTML/CSS/vanilla-JS frontend for the Cosmos Foundation website, built to the "Print & Ember" design system. No framework, no bundler, no build step required to run it.

## Run it

```bash
npx serve .
```

Open the printed URL (e.g. `http://localhost:3000`). That's it — every page is a plain `.html` file, every script is a native ES module (`<script type="module">`), and every stylesheet is plain CSS with custom properties. You can also open `index.html` directly in a browser for a quick look, but a static server is required for the pages that `fetch()` JSON (most of them) — `file://` blocks those requests.

**Important — `serve` and query strings.** By default `serve` "cleans" URLs by 301-redirecting `page.html` → `/page`, and in doing so drops any `?query`. Since `board-member.html?id=…`, `initiative.html?id=…` and `event.html?id=…` all rely on the query string, this repo ships a `serve.json` (`{ "cleanUrls": false, "trailingSlash": false }`) that turns that behaviour off. If you deploy to a host with similar "clean URL" behaviour (Vercel, Netlify, etc.), make sure it's configured the same way, or those three pages will 404 on real links.

## Regenerate the generated assets

Two tools do all the codegen. Both are idempotent — safe to re-run any time source photos change.

```bash
npm install          # installs sharp, the only dependency (dev-only, image conversion)
npm run images       # tools/convert-images.mjs: source/** -> assets/img/**, plus assets/data/images*.json
npm run events       # tools/scan-events.mjs: source/events/<folder> -> assets/data/events.js + assets/data/galleries/*.json
npm run verify       # tools/verify.mjs: dead links, missing alt/width/height, stray source/uploads refs, duplicate ids
npm run build        # runs all three in order
```

Run `images` before `events` — the event scanner reads the per-event image chunks the converter writes.

## Folder map

```
/
├─ *.html                    13 pages — see HANDOVER.md for which are static vs data-driven
├─ assets/
│  ├─ css/
│  │  ├─ tokens.css          design tokens (colours, type, motion, spacing)
│  │  ├─ fonts.css           metric-matched fallback @font-face (avoids swap-induced CLS)
│  │  ├─ base.css            reset, typography helpers, texture layers, reveal-on-scroll
│  │  ├─ layout.css          container, header/nav, footer, grid helpers
│  │  ├─ components/         buttons, cards, slider (carousel), lightbox
│  │  └─ pages/              one stylesheet per page, only the page-specific rules
│  ├─ js/
│  │  ├─ main.js             per-page bootstrap: header/footer, theme, nav, reveal
│  │  ├─ partials.js         renders header/footer from data/site.js
│  │  ├─ theme.js            dark/light toggle (see the inline blocking script in each <head> for first-paint)
│  │  ├─ reveal.js           IntersectionObserver scroll reveals
│  │  ├─ img.js              images.json lookup -> <img> with srcset/sizes/width/height
│  │  ├─ ink.js              maps a decorative accent-ink CSS var to its text-safe variant
│  │  ├─ components/         slider.js (carousel), lightbox.js (gallery viewer), nav.js (mobile menu, dropdown)
│  │  └─ pages/               one small script per page — reads ../../data/*.js, renders into the page's mount points
│  └─ data/                  assets/data/*.js — see HANDOVER.md for schemas
│     ├─ board.js, initiatives.js, series.js, media.js, site.js, about.js   (hand-authored, carried over from the approved mockup)
│     ├─ events.js                                                          (generated by tools/scan-events.mjs)
│     ├─ images.json                                                        (generated by tools/convert-images.mjs — logos/cosmosfoundation/cosmos-gallery/hero)
│     ├─ images/events/<slug>.json, images/event-covers.json                (generated — per-event and cover-only image metadata)
│     └─ galleries/<slug>.json                                              (generated — one event's full photo list)
├─ source/                   RAW photo library. Read-only input to the image pipeline — never edited, never shipped.
├─ tools/
│  ├─ convert-images.mjs     the image pipeline
│  ├─ scan-events.mjs        the event-folder scanner
│  ├─ verify.mjs             pre-launch checks
│  └─ lib/                   shared parsing logic (event folder-name dates/slugs/sections, filename slugify, magic-byte image detection)
├─ HANDOVER.md                backend integration notes
└─ serve.json                 disables `serve`'s clean-URL redirect (see above)
```

There is no `assets/js/data/` folder — data modules live at `assets/data/`, one level up from `assets/js/`; page scripts import them as `../../data/*.js`.

## Design system

`system.html` is a living reference for the palette, type scale, textures and components — open it after any visual change as a quick regression check.

## Known-bad source files

At least four files under `source/cosmosfoundation/` and one per event folder's `Thumbs.db` are not real images (Windows thumbnail cache files, or in four cases 355-byte saved HTML error pages wearing a `.jpg` extension). `convert-images.mjs` detects and skips these by magic bytes, not extension, and lists every skip in its console output.

## Lighthouse (measured)

Run with `npx lighthouse <url> --preset=desktop`, against `npx serve .` locally, after `npm run build`:

| Page | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| `index.html` | 97 | 100 | 96 | 100 |
| `events.html` | 95 | 100 | 100 | 100 |
| `event.html?id=thai-ambassador-welcome-dinner` | 97 | 100 | 100 | 100 |

CLS is 0–0.03 on every page (the ~0.02 that shows up on most pages is the header's nav populating from `partials.js` after first paint — inherent to rendering nav from one JS-driven source per the architecture; a hard 0 would mean duplicating the nav into static markup on every page). LCP is ~1.0–1.2s, TBT is 0ms.

`best-practices` sits at 96 rather than 100 on `index.html` only while `assets/video/hero.mp4` is genuinely absent from the repo (see the Known-bad section below and HANDOVER.md §6) — the homepage's existence check for the hero video is a real network request, and Chrome logs any failed request to the console regardless of which API made it (fetch() included), so one 404 shows up in Lighthouse's console-errors audit until the video ships. It resolves itself the moment `hero.mp4`/`hero.webm` are added — no code change needed.

**Mobile-throttled numbers are lower** (~75–95 Performance under Lighthouse's default mobile CPU/network throttling, vs. 95–97 under `--preset=desktop`) — expected for a no-bundler, plain-ES-modules site: the import graph (page script → main.js → partials/theme/nav/reveal → img.js → several data modules) is several small sequential requests, which Lighthouse's simulated slow-4G/4x-CPU profile penalizes far more than it penalizes real HTTP/2 hosting. Deploying to any HTTP/2-capable static host (Netlify, Vercel, CloudFront, etc. — practically everything but a bare `serve .`) collapses most of that penalty via request multiplexing. If mobile-throttled scores need to hit ≥95 too, the lever is bundling `assets/js/**` (esbuild with no other config produces a single flat file); the brief allows an optional build step for exactly this reason, but this repo ships un-bundled by default so nothing has to be installed to run it.

## Browser support

Last two versions of Chrome, Safari, Firefox, Edge, and iOS Safari. No polyfills are shipped; nothing in the codebase requires anything newer.
